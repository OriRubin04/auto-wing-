# התקנה על Raspberry Pi 5 וחיווט במטוס

מסלול אחד, שבעה שלבים, בסדר הזה. אם משהו לא עובד — טבלת התקלות בסוף.

כל החישוב רץ על הפאי. התחנה הקרקעית רק שולחת את הקליק על המטרה ומקבלת וידאו,
והמטוס ממשיך לעבוד גם כשהקישור מת (CLAUDE.md סעיף 1).

**אין אימג׳ מוכן להורדה.** שלב 2 הוא התחליף: פקודה אחת שעושה את הכול. אחרי
שהכרטיס עובד, גבה אותו — ראה את הפרק לפני האחרון.

## מה צריך

| חלק | פירוט |
|---|---|
| Raspberry Pi 5, 8GB | עם המאוורר הפעיל. הוא מוריד תדר ב‑85 מעלות |
| כרטיס microSD | 32GB ומעלה |
| מצלמת USB | זו שאיתה בדקת |
| כבל JST-GH בן 6 פינים | למחבר TELEM2 בבקר הטיסה |
| שלושה חוטי מגשר נקבה‑נקבה | מהכבל הזה אל פיני ה‑GPIO בפאי |
| ממיר מתח (BEC) ל‑5V‏ 5A | עם מוצא USB-C‏. מוקדש לפאי בלבד |

## שלב 1 — צריבת הכרטיס

ב‑**Raspberry Pi Imager** בחר **Raspberry Pi OS (64-bit) Lite**. דווקא Lite:‏
שום דבר על המטוס לא פותח חלון.

לפני הכתיבה לחץ על גלגל השיניים (**Edit Settings**) והגדר:

- שם מחשב `autowing`, שם משתמש `pi` וסיסמה
- **הפעל SSH** עם אימות סיסמה
- את רשת ה‑Wi-Fi שלך

הכנס את הכרטיס, חבר מתח, והתחבר מהמחשב הנייד:

</div>

```
ssh pi@autowing.local
```

## שלב 2 — התקנה

פקודה אחת. היא אידמפוטנטית, אפשר להריץ אותה שוב בבטחה:

</div>

```bash
git clone -b claude/tender-hamilton-Dz0Se https://github.com/OriRubin04/auto-wing-.git ~/auto-wing-
bash ~/auto-wing-/tools/install_pi.sh
sudo reboot
```

<div dir="rtl">

האתחול נדרש: הסקריפט מוסיף `usb_max_current_enable=1` לקובץ ההגדרות של
האתחול. בלי זה פאי 5 שמוזן מספק שאינו USB-PD מגביל את כל אביזרי ה‑USB
ל‑600 מילי־אמפר, והמצלמה נעלמת באמצע טיסה בלי שום הודעת שגיאה.

הסקריפט גם מתקין את התלויות, בונה סביבה וירטואלית, ומכין שירות `systemd`
שנשאר **מושבת** עד שלב 7.

## שלב 3 — חיווט

### נתונים: פאי אל בקר הטיסה

חיבור ישר, בלי שום ממיר. שני הצדדים עובדים בלוגיקה של 3.3V, ולכן אין צורך
בממיר רמות ואין צורך בממיר USB. שלושה חוטים:

</div>

```
  Raspberry Pi 5  (40-pin header)        FC TELEM2  (6-pin JST-GH)
  ┌──────────────────────┐              ┌──────────────┐
  │ pin 8   GPIO14  TXD ─┼─────────────►│ 3   RX       │
  │ pin 10  GPIO15  RXD ◄┼──────────────┤ 2   TX       │
  │ pin 6           GND ─┼──────────────┤ 6   GND      │
  │                      │              │ 1   +5V   ×  │
  └──────────────────────┘              └──────────────┘
```

<div dir="rtl">

- **TX אל RX, ו‑RX אל TX.** מוצלב. הפוך נותן בדיוק את התסמין של מחבר מת:
  אין פעימת לב ואין שגיאה.
- **את פין 1 של ה‑TELEM לא מחברים.** זה מתח 5V, והפאי מוזן מה‑BEC שלו.
  חיבורו מחבר שני פסי 5V זה לזה.
- **GND חובה.** בלעדיו הקישור לא יעבוד, או יעבוד לא יציב.
- **אל תטעה בפינים.** בפאי, פין 2 ופין 4 הם 5V, וחיבור שלהם לאחד מהאלה הורג
  את הפאי. ספור את הפינים בעזרת שרטוט לפני שאתה מחבר.
- מספרי הפינים בצד בקר הטיסה הם התקן Pixhawk. **בדוק את ההדפס על הלוח שלך**,
  פין 1 מסומן.

### ודא שההתקן קיים

סקריפט ההתקנה הוסיף `dtparam=uart0=on` לקובץ האתחול, ולכן אחרי האתחול של
שלב 2 אתה אמור לראות את ההתקן:

</div>

```bash
ls -l /dev/ttyAMA0
```

<div dir="rtl">

אם הוא לא קיים — טבלת התקלות.

> **אל תשתמש ב‑`/dev/serial0` בפאי 5.** בכל דגם אחר הוא מצביע ל‑UART של
> GPIO14/15, אבל בפאי 5 הוא מצביע למחבר הדיבאג הנפרד — מחבר אחר לגמרי, שלא
> מחובר לשום דבר. זו הטעות שתמצא בכל מדריך שנכתב לפאי 3 ו‑4. השתמש
> ב‑`/dev/ttyAMA0` במפורש.
>
> בפאי 5 יש גם חדשה טובה: מסוף הבקרה של לינוקס יושב מראש על מחבר הדיבאג הזה
> ולא על GPIO14/15, ולכן אין צורך לשחרר אותו ב‑raspi-config כמו בדגמים
> הקודמים.

### מתח

</div>

```
  Main battery ──┬── ESC ── motor
                 ├── FC power module ──► flight controller
                 └── 5V / 5A BEC ──────► Raspberry Pi 5  (USB-C)
```

<div dir="rtl">

- **ממיר מתח נפרד לפאי.** לא מפין ה‑5V של ה‑TELEM — הוא מוגבל לאמפר אחד
  בקירוב ומשותף. פאי שהמתח שלו צונח נופל, ונפילה באוויר מאבדת את המעקב.
- המצלמה ישר לפורט USB בפאי, לא דרך מפצל.

## שלב 4 — פרמטרים בבקר הטיסה

ב‑Mission Planner‏: **Config → Full Parameter List**. שלושה פרמטרים:

| פרמטר | ערך |
|---|---|
| `SERIAL2_PROTOCOL` | `2` |
| `SERIAL2_BAUD` | `921` |
| `BRD_SER2_RTSCTS` | `0` |

כתוב (Write Params) ואפס את הבקר.

## שלב 5 — הגדרות

על הפאי:

</div>

```bash
nano ~/auto-wing-/config/config.yaml
```

<div dir="rtl">

שנה ארבע שורות:

</div>

```yaml
camera:
  width: 1280                         # במקום 640
  height: 720                         # במקום 480

mavlink:
  connection_string: "/dev/ttyAMA0"
  baudrate: 921600
```

<div dir="rtl">

הרזולוציה היא לא קוסמטיקה: ב‑640×480 רכב באורך 4.5 מטר תופס עשרה פיקסלים
מגובה 250 מטר, וזה על הרצפה שמתחתיה שום דבר לא עובד (CLAUDE.md סעיף 6).
1280×720 מכפיל את זה בחינם.

ובמחשב הנייד, בקובץ ההגדרות **שלו**:

</div>

```yaml
gcs:
  onboard_ip: "192.168.1.xxx"   # הרץ `hostname -I` על הפאי
```

## שלב 6 — בדיקה על השולחן

**בלי מדחפים. בכלל.**

1. בקר הטיסה מחובר ב‑USB למחשב הנייד, והפאי מחובר ל‑TELEM2. שני הקישורים
   עובדים במקביל.
2. הדלק את המשדר. **ודא שמפסק מצבים מחזיר את המטוס ל‑MANUAL, וודא שהוא עושה
   את זה גם בעודו הפאי שולח פקודות.** זו האפשרות שלך לנטוש. זה הדבר הראשון
   לבדוק, לא האחרון.
3. על הפאי:

</div>

```bash
cd ~/auto-wing- && source venv/bin/activate
python onboard/main.py
```

<div dir="rtl">

   אתה אמור לראות `Heartbeat from sysid=1`‏. אם לא — טבלת התקלות.

4. במחשב הנייד הרץ `python gcs\gcs_client.py` ולחץ על מטרה. ב‑Mission Planner
   ודא: המצב עובר ל‑**ACRO**, הערכים `ch1in` ו‑`ch2in` נעים עם המטרה, ומשטחי
   ההיגוי נעים לכיוון הנכון — מטרה בשמאל התמונה אמורה לגרום לרצון להתגלגל
   שמאלה.
5. העבר את המטרה למרכז. המאזנות אמורות להתייצב, לא להתנדנד. אם הן מתנדנדות,
   הורד את `control.roll_pid.kp`‏.
6. פתח את `logs/<timestamp>/flight.csv` ובדוק `loop_ms` (שלא עלה מעל 50) ואת
   `confidence`‏.

## שלב 7 — הפעלה אוטומטית

רק אחרי ששלב 6 עבר במלואו:

</div>

```bash
sudo systemctl enable --now autowing
journalctl -u autowing -f
```

<div dir="rtl">

לעצור: `sudo systemctl disable --now autowing`‏.

## אם משהו לא עובד

| תסמין | מה לעשות |
|---|---|
| אין `Heartbeat` | TX ו‑RX הפוכים. זו הסיבה בתשעה מתוך עשרה מקרים — החלף ביניהם |
| אין `Heartbeat`, והחוטים נכונים | בדוק ששלב 4 נכתב ושהבקר אופס |
| `/dev/ttyAMA0` לא קיים | הוסף `enable_uart=1` ל‑`/boot/firmware/config.txt` בנוסף ל‑`dtparam=uart0=on`, ואתחל. שורת ההגדרה הנדרשת משתנה בין גרסאות מערכת ההפעלה |
| לא מצליח לגרום ל‑`ttyAMA0` להופיע | מעקף: ממיר USB↔TTL ברמת 3.3V בין פורט USB בפאי ל‑TELEM2, ואז `connection_string` הוא `/dev/ttyUSB0` ואין צורך בשום הגדרת אתחול |
| `Cannot read from camera index` | הרץ `v4l2-ctl --list-devices`, ועדכן את `camera.index` לפי מה שהוא מראה |
| `Permission denied` על `/dev/ttyAMA0` | התנתק והתחבר מחדש ב‑SSH. הסקריפט הוסיף אותך לקבוצת `dialout` וזה נכנס לתוקף בהתחברות הבאה |
| pip מתחיל להדר את OpenCV (לוקח שעות) | עצור ב‑Ctrl+C והרץ: `sudo apt install -y python3-opencv`, אחר כך מחק את `venv` והרץ את סקריפט ההתקנה שוב |
| המצלמה נעלמת אחרי כמה דקות | לא אתחלת אחרי שלב 2, או שה‑BEC חלש |
| הכול נראה תקין אך המטוס מתעלם | פרמטר קבלת ה‑RC override בבקר. ראה ההערה למטה |
| המטוס מתנדנד | הורד את `control.roll_pid.kp`, ואחר כך העלה את `kd` |
| התמונה לא מגיעה לתחנה הקרקעית | `onboard_ip` שגוי, או חומת אש. הפאי צריך 15000/udp ו‑15001/tcp נכנסים, המחשב הנייד 15100/udp |

**על פרמטר קבלת ה‑RC override.** הבקר מתעלם מפקודות ממזהה מערכת שאינו התחנה
הקרקעית המוגדרת שלו. `pymavlink` שולח כמזהה 255 שהוא גם ברירת המחדל, ולכן
בדרך כלל אין מה לשנות. אם צריך: השם הוא `SYSID_MYGCS` עד גרסה 4.6 ו‑
`MAV_GCS_SYSID` מגרסה 4.7. התיעוד של ArduPilot עדיין מציג את השם הישן, אז תן
אמון ברשימת הפרמטרים של הקושחה שלך ולא במסמך — כולל המסמך הזה.

## גיבוי הכרטיס

ברגע שהמערכת עובדת, כבה את הפאי והוצא את הכרטיס. במחשב ה‑Windows, עם קורא
כרטיסים, הרץ **Win32DiskImager** ולחץ **Read**. הקובץ שנוצר הוא האימג׳ שלך.

לשחזר כרטיס תקין בשדה עדיף על לאתר תקלת התקנה בשדה.

## שני דברים לפני הטיסה הראשונה

- **במצב ACRO מקל באפס לא מיישר כנפיים.** הוא מחזיק את זווית הגלגול הנוכחית.
  היישור נעשה בקוד במפורש, מקריאת `ATTITUDE` (CLAUDE.md סעיף 3).
- **איבוד נעילה מצווה כרגע גלגול אפס ולא מעבר ל‑RTL.** זו דחייה מכוונת, אבל
  המשמעות היא שמטרה שאובדת בתוך פנייה — ממשיכה את הפנייה.

טוס עם מרווח גובה ועם אצבע על מפסק המצבים.
